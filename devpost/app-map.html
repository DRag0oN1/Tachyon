From an authorized launch to a visible robot.

Tachyon connects a saved competition-strategy policy, two mechanical architecture proposals, local component assemblies and supported assembly revisions. The current CAD is a partial, independently authored development assembly; its geometry does not establish a complete authentic VEX robot or physical match performance.

Reference route, prepared for review. This page describes actual code and verification. It does not claim the learner completed a code tour, learning reflection, final review or submission.

One failure, three useful places to follow

The reported failure was an expired or missing tab credential being displayed across Home and Strategy. Recovery now starts before the workspace requests private data.

1. Start and reconnect

server/tachyon/cli.py: serve and launch. launch.py writes a mode-600 project-local handoff per port. A fresh terminal can find the current server without knowing its CAD profile.

2. Check before loading

SessionBoundary.tsx checks the real protected workspace API. client.ts strips the URL fragment and holds credentials only in tab storage. Missing and expired sessions receive one connection screen.

3. Follow the actual result

WorkspaceShell.tsx: openFlow, openSavedDesign and edit. Existing policy inference, requalified local assembly data and exact preview/decision responses drive the visible studio.

To change this, start here

  • Playbook phases and explanations: StrategyPanel and strategyPlaybook. Phases derive from actual rollout events; advanced evidence remains available.
  • Design alternatives and realization labels: ArchitecturesPanel. Design 01 can open saved partial CAD; Design 02 remains a distinct schematic.
  • Contextual commands and collapsed core: AiCore. UI decisions call the existing revision service, not text-only fake edits.
  • Assembly revisions and strategy anchors: RealizationService, bindings, and DesignAssemblyScene. Preview keeps accepted data unchanged; Apply, Discard and Undo require real server confirmation.

A practice to reuse

Test the entry path like a new user. A prepared browser tab can hide a launch defect. demo-launch.spec.ts starts without credentials, confirms private APIs stay locked, follows the real authorized link, refreshes and reopens. test_launch.py separately checks restart rotation and retained workspace data. This links a visible requirement to both positive behavior and the access boundary.

Open it again

From the project folder, use .venv/bin/tachyon launch --port 8019 for a running server. Start with .venv/bin/tachyon serve --port 8019 --open if needed; choose the intended private CAD profile as described in README.md. Never include a private owner URL in a recording or submission.
